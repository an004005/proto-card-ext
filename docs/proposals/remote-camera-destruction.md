# 제안: 원거리 카메라 파괴

상태: 미확정 제안. 구현 전이며 `docs/planned.md`로 옮기려면 아래 결정 항목이 닫혀야 한다.

## 문제

카메라를 끄는 방법은 지금 두 가지뿐이다.

- 해킹: Hacking 사거리 안에서 일정 시간 동안만 무력화. 조용하지만 만료된다.
- Force 파괴: 카메라 노드에 서 있어야 한다. 카메라가 보는 자리에 들어가야 하므로 Stealth가 낮으면 파괴하러 가는 길에 이미 걸린다.

원거리·비해킹 빌드(저격총·투척 무기 위주)는 카메라 앞에서 아무 선택지가 없다. "보이는 것을 부순다"가 이 빌드의 정체성인데 카메라만 예외다.

## 제안 A — 저격 파괴 (권장)

| 항목 | 값 |
|---|---|
| 행동 이름 | 카메라 저격 |
| Capability | Perception (조준·거리 판단). Force가 아닌 이유는 아래 |
| 요구치 R | 2 |
| 사거리 | 현재 노드에서 카메라 노드까지 통로 홉 수 ≤ 2. 일방통행·잠긴 문 너머는 불가(시야가 없다) |
| 시간 | 4칸 |
| 소음 | 2 (총성). 소음 발생 위치는 **내 노드**이고, 위협의 조사 대상은 카메라 노드가 아니라 총성 위치다 |
| 흔적 | 카메라 노드에 강한 흔적 1 (파편). 내 노드에는 흔적 없음 |
| 탄약 | 장전된 탄 1발 소모(총기 장착 시). 총기가 없으면 행동 자체가 없다 |
| 결과 | 카메라 영구 파괴(`disabledCameraIds`). 해킹과 달리 만료 없음 |
| 층계 | Perception 통화(시간만)이므로 strained/severe는 시간 +1/+2. 대신 빗나감 대신 **소음 +1**로 청구하는 안을 검토(아래 결정 항목) |

Force 대신 Perception을 고르는 이유는 두 가지다. Force는 이미 "가서 부순다"의 통화이고, 원거리 파괴의 병목은 힘이 아니라 조준이다. 그리고 Perception이 정보 수단에만 머물면 Perception 특화 장비(저격총: perception +1, mobility −1)가 능동 행동을 하나도 갖지 못한다.

## 제안 B — 투척 EMP 소모품

| 항목 | 값 |
|---|---|
| 아이템 | EMP 투척체(소모품 슬롯, 1칸) |
| 사거리 | 1홉 |
| 시간 | 2칸 |
| 소음 | 0 |
| 결과 | 카메라 30칸 무력화(파괴 아님). 같은 노드의 접속 인터페이스도 함께 정지 |

장점은 빌드를 가리지 않는다는 것이고, 단점은 소모품이라 "선택"이 아니라 "재고"가 된다는 것이다. A와 배타적이지 않다.

## 제안 C — 카메라 시야 우회 (비파괴)

파괴 대신 카메라 노드를 "경계 상태" 표시로 두고 Stealth 3 미만이면 통과 시 경계도 +1만 받게 하는 안. 이미 `CAMERA_STEALTH_THRESHOLD`가 비슷한 역할을 하므로 새 행동을 만들지 않는 최소안이다. 원거리 빌드의 정체성 문제는 풀지 못한다.

## 결정이 필요한 항목

1. A의 Capability를 Perception으로 둘지 Force로 둘지. Force로 두면 층계 통화가 소음·내구도라 "빗나가면 시끄럽다"가 자연히 표현된다.
2. A의 사거리를 홉 수로 잴지, 지도 기하 거리로 잴지. 홉 수가 정수 시간 규칙(ADR-0075)과 맞는다.
3. A가 파괴한 카메라의 파편(강한 흔적)이 그 구역 경계도를 올릴지. 올린다면 해킹 대비 확실한 대가가 생긴다.
4. 탄약 소모를 요구할지. 요구하면 총기 없는 빌드는 B로만 대응하게 된다.
