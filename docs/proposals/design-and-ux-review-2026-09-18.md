# 게임 디자인·UI/UX 리뷰 (2026-09-18)

현재 코드(커밋 6f30947 기준)와 `?devScenario=` 화면을 직접 돌려 본 리뷰다. 결론이 난 것은 없고 전부 제안이므로 여기에만 둔다. 확정되면 `docs/planned.md`로 옮긴다. 이미 `design-backlog.md`에 있는 항목(시간이 흘러도 어려워지지 않음, 열쇠 출구, 전투 길이 미검증, 탐색이 공짜가 됨)은 반복하지 않고 그 위에 얹는다.

## 1. 게임 디자인 — 재미의 축

### 1.1 지금 잘 되는 것

- **정보 층위가 곧 재미다.** 무료 인접 시야(위협 유무만) → 값을 치른 관측(내용물) → Perception 깊이(등급·역할축·은엄폐)의 세 층이 "무엇을 사서 볼 것인가"라는 결정을 매 방마다 만든다. 이 구조는 유지할 가치가 있다.
- **층계(여유/표준/무리/위태/불가)** 가 잠금을 이분법에서 "얼마를 치를 것인가"로 바꿔 빌드가 약해도 선택지가 남는다. 버튼에 대가가 미리 붙는 것도 좋다.
- **오버라이드 칩 한 통**은 지도와 전투가 같은 자원을 두고 다투게 해 준다. 런당 3개라는 수가 "지금 쓸까"를 매번 고민하게 만드는 좋은 크기다.
- **조우 3단계**(우위/동률/열세)와 은신 분해식 표기는 판정이 억까로 읽히지 않게 한다.

### 1.2 재미를 깎는 구조적 문제

1. **통로가 결정에서 빠졌다.** 이동이 어디든 1칸이 되면서(ADR-0084) 그래프의 기하는 의미를 잃었고, 지도에서 유일하게 남은 공간 결정은 **특수 엣지**(물리·전자 잠금, 고지대, 일방통행)와 임시 장벽뿐이다. 그런데 그 엣지의 정보는 한 줄 문자열 툴팁에만 있고, 이동 전 도착 위험 예보는 노드를 클릭해 패널을 열어야 나온다. 공간 결정이 몰린 곳의 UI가 가장 빈약하다 → 이번 통로 툴팁 재설계의 근거(§3.1).
2. **위협이 나를 따라잡을 수 없다.** 순찰 5칸 / 추적 3칸 대 내 이동 1칸이라, 위협은 게이지 작업 중에만 위험하다. 이건 의도된 모형이지만, 그 결과 "이동 중 긴장"이 0이고 "작업 중 긴장"만 남는다. 후보: 통로 위 상태(백로그)보다 싼 대안으로, **연속 이동 N칸마다 흔적 강도 +1** 또는 **같은 구역 안에서 3홉 이상 연속 이동 시 순찰이 그 방향으로 재배치**. 이동에 소음·흔적 말고 "따라붙음"이 생겨야 도망이 결정이 된다.
3. **마감이 하나뿐이라 후반이 단조롭다.** 봉쇄는 위협 속도만 올리고 출구 시각을 건드리지 않는다(의도됨). 그래서 계약 완료 후 탈출은 "가장 빠른 길로 A 가동 → 5칸 대기"로 수렴한다. 후보: 봉쇄 중 **출구 경계(exit_guard) 위협을 A에 배치**해 열쇠 출구·가짜 목표 송출·임시 장벽이 탈출 단계에서도 쓰이게 하기. 지금은 이 셋이 계약 중반에만 쓸모가 있다.
4. **과부화 토글에 대가가 없어 결정이 아니다.** 켜 두는 것이 항상 이득이라 시작하자마자 켜고 잊는다(백로그에 있음). 대가가 정해지기 전이라도 **전투 시작 시 OFF로 리셋 + 켜는 데 에너지 1** 정도의 임시 규칙이 있어야 플레이테스트에서 토글의 손맛을 잴 수 있다.
5. **Stealth·Mobility·Perception·Deception이 빌드 축으로 약하다.** 층계 통화로 실제 돈이 되는 것은 Hacking·Force다. 정찰 사거리(Perception 3부터), 가짜 소음(Deception), 고지대(Mobility 3)는 각각 한 군데씩만 걸린다. 한 런에서 "이 빌드라서 이 길로 간다"가 생기려면 **구역 하나에는 반드시 Mobility 전용 지름길(고지대)과 Deception 전용 우회(센서 게이트, 백로그)가 있게 배치 원형에 보장**하는 것이 값싼 방법이다.
6. **전투와 지도가 서로를 거의 모른다.** 지도에서 전투로 넘어가는 것은 시간(3칸/라운드)·시체·소음뿐이고, 전투 결과가 지도로 돌아오는 것은 시체와 내구도뿐이다. 후보: 전투 승리 시 **그 위협의 순찰 자리가 비어 증원까지 그 경로가 안전**해지는 것을 지도에 표시(지금은 로스터만 줄고 화면은 조용하다), 전투에서 **소음 게이지가 찼을 때 인접 위협이 조사로 전환**(전투 소음 게이지가 지금은 표시만 된다면 이것이 첫 활용처).

### 1.3 인지 부하

한 런에 플레이어가 배워야 하는 시스템이 많다: Capability 6종 + 층계 5단계 + 접근 모드 3 + 게이지 + 경계도 단계·압력 + 소음 + 흔적·시체 + 카메라·인터페이스·발전기·통제실 + 계약 3유형 + 오버라이드 칩 + 과부화 + 출구 A·열쇠. 프로토타입이라 전부 노출하는 것은 맞지만, **첫 런에서 만나는 순서**를 배치 원형이 통제하지 않는다. 후보: 입구·관리동(시작 구역)의 원형에는 잠금 엣지 1·카메라 1·보급품만 두고 인터페이스·발전기·고지대는 두 번째 구역부터. 코드 변경은 `facilityLayout.js`의 구역 원형 한 줄씩이다.

## 2. UI/UX 리뷰

### 2.1 지도 화면

- **상단 시계가 같은 숫자를 세 번 말한다.** "가장 이른 마감 출구 A 폐쇄 50칸 · 시각 0/80 · 붕괴까지 80칸 · A 폐쇄까지 50칸". 가장 이른 마감이 A일 때 "A 폐쇄까지 50칸"은 중복이다. 가장 이른 것 하나를 굵게, 나머지는 그것과 다를 때만.
- **통로 툴팁**: §3.1.
- **노드 → 이동이 두 단계다.** 클릭해 선택 → 패널의 "이 노드로 이동". 인접 노드는 더블클릭으로 바로 이동할 수 있어야 한다. 힌트도 "클릭해 선택 · 더블클릭해 이동".
- **위협 표식 `▲1`은 수만 말한다.** 순찰인지 추적인지, 몇 칸 뒤에 움직이는지는 카드나 패널을 열어야 나온다. 추적 중인 위협은 표식 자체가 달라야 한다(채움 삼각형 + 남은 칸).
- **호버 카드가 마우스를 한 프레임 늦게 따라온다**(rAF 합치기의 대가). 카드가 커서를 따라다니지 않고 **엣지·노드에 고정**되면 지연이 안 보이고 읽기도 편하다. 통로 툴팁부터 고정 배치로 간다.
- **범례가 `?` 버튼 뒤에 숨어 있다.** 노드 유형 8종이 형태(원·사각·삼각·오각)로만 구분되는데, 첫 런에서는 형태 → 이름이 외워지지 않는다. 지도 줌이 3배 이상이면 노드 옆에 유형 약자를 함께 그리는 것이 범례보다 낫다.
- **패널이 길다.** 현재 노드 패널에 오버라이드 칩·정찰·대기·은엄폐·인터페이스·카메라·발전기·통제실·파밍·환경 조작·현장 장비·계약이 한 열로 쌓인다. 접히는 그룹("지금 여기서 할 수 있는 것" / "수습" / "장비")이 필요하다. 지금은 스크롤로 버튼을 찾는다.

### 2.2 전투 화면

- **화면의 60%가 비어 있다.** 플레이어·적 카드가 상단 중앙 작은 박스 두 개이고 손패는 맨 아래다. 원본 브레인스토밍 메모(scratch.md)의 "플레이어와 몬스터를 더 가깝게, 디버프·방어도 잘 보이게"가 아직 반영되지 않았다. 적 인텐트는 삼각형 하나와 숫자뿐이다.
- **이 전투가 지도 시간을 얼마나 먹는지 안 보인다.** 상단 시계는 있지만 "라운드 N · 이 전투 3N칸"이 없다. 백로그의 "전투 길이 가정 미검증"을 플레이테스트에서 확인하려면 이 숫자가 화면에 있어야 한다.
- **소모품 버튼(붕대 ×3)이 카드와 같은 층위에 없다.** 손패 위 왼쪽 구석의 작은 버튼이라 존재를 잊는다.

### 2.3 조우 패널

잘 되어 있다. "내 은신 −2 < 적 지각 0"의 큰 숫자 비교와 분해식이 좋다. 하나만: 열세일 때 "유효 유료 행동 1회만 허용"이 무엇을 뜻하는지(정찰은 되고 이동은 되나?)가 문장으로만 있어, 패널 아래에 **지금 허용되는 버튼 목록**이 있으면 좋다.

## 3. 이번에 진행하는 것

### 3.1 통로 툴팁 재설계 (구현 진행)

디자인: `게임 UI 목업 디자인/edge-tooltip/`(Before / Main / States, 미리보기 https://claude.ai/artifact/LKUY2QjMJjnBqCQFMs87QR).

- 머리: 통로 종류 + 상태 배지 + 양 끝 노드 **유형**과 구역(현재 위치인 끝은 "현재 위치").
- 행: 잠금(표준·현재·층계·개방 예보), 고지대(부족분·HP), 이동(1칸 + 도착 위험 예보, 인접일 때만), 방향(일방통행), 장벽(남은 칸).
- 꼬리: 규칙 한 줄 + 조작 힌트.
- 노드 카드와 같은 컴포넌트 뼈대와 토큰을 쓴다. 내용은 `describeEdge`가 정하고 카드는 그리기만 한다.

### 3.2 함께 진행하는 작은 UX 개선

- 상단 시계 중복 제거.
- 인접 노드 더블클릭 이동 + 힌트 문구.
- 전투 상단에 라운드 수와 이 전투에 쓴 칸 표시.
- 지도 위협 표식에 모드(추적이면 채움) 표시.

## 4. 보류 — 플레이테스트 뒤에 정할 것

§1.2의 2·3·5·6은 규칙 변경이라 지금 손대지 않는다. 플레이테스트에서 확인할 질문은 순서대로: (a) 이동 중에 긴장이 있는가, (b) 계약 완료 후 탈출이 매번 같은가, (c) Hacking·Force 말고 다른 Capability에 투자한 런이 다르게 느껴지는가.
