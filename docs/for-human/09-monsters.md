# 09. 몬스터

## 이 시스템이 하는 일

몬스터는 **고정된 순환 행동열**을 가진다. 무작위 분기가 있는 자리도 인텐트를 표시하는 순간 한 번만 굴려 확정하므로, 화면에 보이는 인텐트와 실제로 실행되는 행동이 언제나 같다. 맵의 위협 마커는 구역과 규모만 들고 있고, 실제 몬스터 구성은 구역별 편성 풀에서 뽑는다.

## 규칙과 수치

### 몬스터 정의의 모양

```js
{ id, name, hp, isMachine, tier, perception,
  sequence: [ Move | { random: [{ weight, move }, ...] } ],
  phase2Sequence?, phaseTransitionHpFraction?, startingStatuses? }
```

- `Move` = `{ id, mapNoise, damage, hits?, effects?, summon?, insertStatusCard?, insertStatusCardCount? }`
- `effects`는 카드와 **같은 해석기**를 쓴다(`target`은 `'self'` 또는 `'player'`).
- `mapNoise`(0~3)는 맵 소음 전용이며 피해 계산의 `attackKind`와 별개다.
- `tier`: `normal` / `elite` / `boss` / `minion`. `minion`은 맵 노드에 직접 배정되지 않고 다른 몬스터의 `summon`으로만 등장한다.

### tier별 맵 지각 (`perception`)

조우 판정에서 위협 쪽 값은 `마커의 alert + 구성 몬스터의 perception 중 최댓값`이다.

| tier | perception |
|---|---|
| 일반 `normal` | −1 |
| 엘리트 `elite` | 0 |
| 보스 `boss` | 1 |
| 미니언 `minion` | −1 (실질 미사용) |

| 규칙 | 코드 필드 | 쓰는 몬스터 |

### 무작위 분기의 처리

- `{ random: [...] }` 항목은 **AI 커서가 그 자리에 처음 닿을 때 딱 한 번** 굴리고, 뽑힌 행동을 `aiState.resolvedMove`에 캐시한다.
- 인텐트 표시와 실제 실행이 같은 `aiState`를 읽으므로 둘이 갈라질 수 없다.
- 보스 2단계 전환도 `createInitialAiState(..., phase)`로 AI 상태를 새로 만든다 — 2단계 시퀀스가 더 짧아도 인덱스가 범위를 넘지 않는다.
- 여러 마리가 같은 종이면 `staggerIndex`로 시작 인덱스를 어긋나게 해 같은 행동을 동시에 하지 않는다.

### 위협 마커 → 전투 편성

편성은 `pickThreatEncounter(rngState, sectorId, size)` (`src/data/dropTables.js`)가 정한다.

- 마커의 `size` ≥ 4이면 그 구역의 **엘리트 풀**, 아니면 **일반 풀**에서 하나를 균등 추첨한다.
- 구성은 런 시작 시 마커별로 한 번 고정되며, 전투 진입 시에도 그대로 재사용된다. 무시·회피로 끝난 조우는 롤을 소모하지 않는다.

| 구역 | 일반 풀 | 엘리트 풀 |
|---|---|---|
| 입구·관리동 | 니빗×2 / 잉클릿×3 / 자폭충 | 맹금 바이도니스 |
| 실험동 | 자폭충+복슬지렁이 / 마울러 / 날개버섯+나뭇잎 슬라임 / 나뭇잎+가지 슬라임 | 게구리 기생체 |
| 격납고·물류창고 | 마울러 / 큐브형 구조체×2 / 마울러+자폭충 | 낡은 석상 |
| 보안·격리동 | 큐브형 구조체 | 낡은 석상 |
| 동력·정비동 | 덩굴 셰임블러 / 포그모그 / 교살마+잭스프루트 | 낡은 석상 |
| 폐기물 처리장 | 포그모그×2 / 교살마 / 덩굴 셰임블러+잭스프루트 | 게구리 기생체 |
| 통신·관제탑 | 큐브형 구조체 / 날개버섯×2 / 잉클릿+큐브형 구조체 | 낡은 석상 |
| 거주동 | 니빗×2 / 잉클릿+자폭충 / 가지+나뭇잎 슬라임 | 맹금 바이도니스 |

- 위협 마커의 `size`(2~4)는 **편성 풀을 고르는 기준**이고, 실제 등장 마릿수는 뽑힌 템플릿이 정한다 — 규모 3짜리 마커가 몬스터 한 마리와 싸우는 편성으로 풀릴 수 있다(코드에서 확인).
- **보스는 어떤 구역 편성 풀에도 들어 있지 않다.** 네 보스 정의는 존재하지만 현재 위협 마커 경로로는 등장하지 않는다(코드에서 확인 — `SECTOR_THREAT_POOLS`).

### 전투 시작 시 걸리는 보정

| 조건 | 효과 |
|---|---|
| 그 구역 발전기가 살아 있음 | 적 전원 갑옷 `GENERATOR_COMBAT_START_ARMOR` = 5 |
| 임플란트 ② 위협 감지 장착 | 적 전원 취약1 · 약화1 |
| 플레이어 기습(우위 조우) | 적 전원 스턴 후 플레이어 선공 |
| 적 기습(열세·강제 조우) | 적이 한 번 먼저 행동 + 맵 3칸 추가 청구 |

`hpMultiplier`를 전달하는 경로가 `startCombat`에 있으나, 맵 조우 경로에서는 사용하지 않는다(코드에서 확인).

## 기획 의도

- **인텐트는 공개되고 확정된다**. 무작위 분기를 표시 시점에 한 번만 굴리는 구조는 "적 인텐트를 숨기고 행동을 완전 무작위로 바꾸는 것은 핵심 훼손"이라는 제품 기준([game-core-and-variables.md](../game-core-and-variables.md) 적용 예시)의 구현이다.
- **행동열이 순환 고정인 이유**: 플레이어가 몇 턴 뒤에 무엇이 오는지 셀 수 있어야 카드 한 장의 사용 시점이 결정이 된다.
- **위협 구성이 조우 판정에 들어오는 이유**(ADR-0077): 규모 4가 잡몹 넷인지 보스 하나인지 모르면 싸울지 피할지 고를 수 없다. 그래서 구성은 Perception 3 이상의 정찰로만 읽히고, 눈앞의 조우 패널은 접촉이므로 언제나 낸다.
- **현재 로스터는 임시(v1)다.** 원래 구 8층 "과성장 폐허" 테마용으로 만든 몬스터를 시설맵 여덟 구역에 이름과 설정으로 유추해 재배분한 것이다 — 정밀 밸런싱과 정식 로스터 교체는 후속 과제다(`src/data/dropTables.js` 주석).
- **엘리트가 규모 4에만 붙는 이유**: 규모가 곧 위험의 예고가 되게 하려는 것이다. 규모는 무료 인접 관측으로도 서 있는 자리에서는 읽히므로, 최소한 "저기는 크다"는 경고가 공짜로 온다.
